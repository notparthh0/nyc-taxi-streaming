01 — Kafka Producer
producer.py
Reads NYC TLC Yellow Taxi Parquet data, validates and sorts records chronologically, then streams JSON-serialized trip events to the Kafka topic at a configurable rate (PRODUCER_SLEEP_SECONDS from env).
python kafka-python-ng pandas parquet
JSON events → topic: nyc-taxi-stream
⚡
02 — Kafka Topic
docker-compose.yml · nyc-taxi-stream
Distributed message bus running via Docker Compose. Producer sends JSON records containing tpep_pickup_datetime, PULocationID, fare_amount, trip_distance, and passenger_count. Validated on ingestion before queuing.
Confluent 7.5.0 PLAINTEXT Docker
poll() · batch consume
⚙️
03 — Stream Consumer
consumer.py
Subscribes to the Kafka topic, deserializes JSON messages, validates required fields, and routes events into 5-minute tumbling windows bucketed by pickup zone (PULocationID). Maintains a rolling 12-window history per zone for statistical baseline.
python statistics kafka-python-ng
window close → aggregated metrics per zone
🪟
04 — 5-Min Tumbling Window Engine
consumer.py · WindowAggregator
Groups events into non-overlapping 5-minute windows. On window close, computes avg_fare, trip_count, avg_distance, avg_passengers per zone. Flushes final window on consumer shutdown to prevent data loss.
tumbling windows zone aggregation final flush
count > mean + 2σ → anomaly flagged
🔍
05 — Anomaly Detector
consumer.py · detect_anomaly()
Applies a statistical threshold: flags a zone as anomalous when its trip_count exceeds mean + 2 standard deviations across the rolling 12-window history. Triggers LLM diagnosis on positive detection.
mean + 2σ rolling 12-window per-zone baseline
anomaly context → Gemini API call
🤖
06 — Gemini LLM Diagnosis
consumer.py · google-genai · gemini-2.5-flash
On anomaly detection, sends zone metrics + historical context to Gemini 2.5 Flash via google-genai SDK. Returns natural-language root-cause diagnosis (time-of-day patterns, zone characteristics, demand magnitude analysis).
google-genai gemini-2.5-flash prompt engineering
diagnosis stored · capped at 100 entries
🗄️
07 — In-Memory State Store
consumer.py · shared state
Holds live window results (all zones, current window) and the last 100 anomaly records with LLM diagnoses. Capped to prevent unbounded memory growth. Shared between consumer thread and Streamlit dashboard via thread-safe access.
in-memory capped at 100 thread-safe
reads live state · auto-refresh 5–60s
📊
08 — Streamlit Dashboard
dashboard.py
Real-time monitoring UI: live metrics cards (total trips, active zones, anomalies), top-10 zone bar chart, anomaly review table with LLM diagnosis column, and a refresh-rate slider (5–60s). Reads directly from the shared in-memory store.
streamlit streamlit-autorefresh altair
